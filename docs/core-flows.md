# Core flows

These are the flows a visitor or the owner relies on the site for, each with the tests that cover it at three levels: unit (one module, no network), integration (several parts together, outside services played by stand-ins) and UI (a real browser driving the running site). `scripts/check-site.mjs` checks this file: every named test must exist under that exact title, and `Gaps allowed` must equal the number of `—` cells, a number that only ever goes down.

Where they live and how they run (none of them is deployed: the Site workflow leaves `tests/` out):

- Unit, `tests/unit/`, and integration, `tests/integration/`: Node's built-in test runner, `node --test`. They run the pages' scripts against the real pages with `tests/support/` (a small stand-in DOM, a fixed clock, and stand-ins for GitHub's API, the snapshot, location and localStorage).
- UI, `tests/ui/`: Playwright drives Chromium against the site served by `python3 -m http.server`, with GitHub, GoatCounter, Google Fonts and the linked sites played by `tests/ui/stand-ins.js`. Run with `tests/ui/run.sh` (Playwright via `npx`).
- All three levels run on every push and pull request, and the site deploys only when they pass. No test calls a live service.

Gaps allowed: 0
